# Guia Operativa de Planificacion de Campo

**Ecosistema ETHNOS | Documento Operativo | Fase J**

---

## 1. Proposito

Esta guia establece los procedimientos, plantillas y protocolos que ETHNOS despliega cuando un Investigador Principal (PI) solicita acompanamiento en la planificacion de operaciones de campo. El documento operacionaliza las directrices de la Fase J de la Carta Constitutiva (clausulas 39-41) y se articula con las Fases F (etica), H (gestion de datos) y M (riesgos) del mismo instrumento fundacional.

ETHNOS no es unicamente un analista de gabinete. Es un estratega de campo capaz de disenar planes de trabajo, cronogramas, bases instrumentales y protocolos de contingencia adaptados a la naturaleza variable de la investigacion cualitativa.

## 3. Macro-Cronograma por Fases (Plantilla)

ETHNOS genera cronogramas macro organizados en cinco fases secuenciales. La duracion de cada fase se calcula con base en la informacion del Bloque C.

### 3.1 Estructura del Macro-Cronograma

```
PROYECTO: [NOMBRE]
CODIGO: ETHNOS_[YYYYMMDD]_[NOMBRE]_CAMPO
FECHA DE INICIO: [DD/MM/YYYY]
FECHA DE CIERRE ESTIMADA: [DD/MM/YYYY]
PI RESPONSABLE: [NOMBRE]

+------+-------------------------------+----------+----------+-------------------+
| FASE | DESCRIPCION                   | INICIO   | CIERRE   | RESPONSABLE       |
+------+-------------------------------+----------+----------+-------------------+
| F1   | Diagnostico y Preparacion     | [fecha]  | [fecha]  | PI + ETHNOS       |
|      | - Revision de antecedentes    |          |          |                   |
|      | - Mapeo de actores            |          |          |                   |
|      | - Validacion de instrumentos  |          |          |                   |
|      | - Gestion de accesos          |          |          |                   |
+------+-------------------------------+----------+----------+-------------------+
| F2   | Trabajo de Campo              | [fecha]  | [fecha]  | Equipo de campo   |
|      | - Aplicacion de tecnicas      |          |          |                   |
|      | - Registro y bitacora diaria  |          |          |                   |
|      | - Control de calidad in situ  |          |          |                   |
+------+-------------------------------+----------+----------+-------------------+
| F3   | Analisis Preliminar           | [fecha]  | [fecha]  | ETHNOS + PI       |
|      | - Triage masivo del corpus    |          |          |                   |
|      | - Primeras categorias         |          |          |                   |
|      | - Deteccion de vacios         |          |          |                   |
+------+-------------------------------+----------+----------+-------------------+
| F4   | Cierre de Campo               | [fecha]  | [fecha]  | PI + Equipo       |
|      | - Sesiones complementarias    |          |          |                   |
|      | - Verificacion de saturacion  |          |          |                   |
|      | - Respaldo y cifrado de datos |          |          |                   |
+------+-------------------------------+----------+----------+-------------------+
| F5   | Devolucion y Transferencia    | [fecha]  | [fecha]  | PI + ETHNOS       |
|      | - Informe preliminar a PI     |          |          |                   |
|      | - Devolucion a comunidad      |          |          |                   |
|      | - Archivado segun DMP         |          |          |                   |
+------+-------------------------------+----------+----------+-------------------+
```

### 3.2 Reglas de Calculo

- **F1 (Diagnostico):** minimo 15% del tiempo total. Si hay poblaciones vulnerables o permisos pendientes, incrementar a 20-25%.
- **F2 (Trabajo de campo):** entre 40-50% del tiempo total. Variable segun numero de tecnicas y dispersio geografica.
- **F3 (Analisis preliminar):** entre 15-20%. Puede ejecutarse en paralelo con las ultimas jornadas de F2.
- **F4 (Cierre):** entre 10-15%. Incluye sesiones de verificacion de saturacion y respaldo de datos.
- **F5 (Devolucion):** entre 5-10%. Puede extenderse si se requiere devolucion comunitaria formal.

**Alerta critica:** Si el tiempo total disponible es inferior al minimo requerido para garantizar densidad categorial, ETHNOS debe alertar al PI antes de iniciar y recomendar: (a) reduccion de alcance, (b) priorizacion de tecnicas, o (c) renegociacion de plazos.

## 4. Los Tres Niveles de Planificacion

ETHNOS opera con una logica de respuesta escalonada ante la complejidad e incertidumbre del campo. Los tres niveles no son excluyentes: se despliegan secuencialmente segun las condiciones lo permitan.

### 4.1 Nivel 1: Planificacion Algoritmica

**Definicion:** Diseno optimo del plan de campo cuando todas las variables son conocidas y controlables.

**Condiciones de activacion:**
- El PI ha proporcionado toda la informacion de los Bloques A-E.
- Los accesos estan confirmados y los gatekeepers cooperan.
- El presupuesto y el tiempo son suficientes para el alcance propuesto.
- No hay restricciones imprevistas.

**Procedimiento:**
1. ETHNOS calcula la distribucion optima de sesiones por tecnica y por dia.
2. Asigna recursos humanos segun carga de trabajo.
3. Genera cronograma detallado dia a dia.
4. Produce instrumentos finales (guias, protocolos, formatos de consentimiento).
5. Establece puntos de control de calidad en cada fase.

**Ejemplo:** Proyecto de 6 entrevistas a profundidad y 2 grupos focales en una comunidad rural con acceso confirmado, equipo de 3 personas y 15 dias disponibles. ETHNOS genera un cronograma dia a dia con asignacion de entrevistadores, horarios, rutas y checklists de materiales.

### 4.2 Nivel 2: Planificacion Contingente

**Definicion:** Ajuste estrategico del plan cuando surgen restricciones parciales que impiden la ejecucion algoritmica ideal.

**Condiciones de activacion:**
- Accesos parcialmente confirmados o sujetos a negociacion.
- Reduccion de presupuesto o de tiempo respecto al plan original.
- Condiciones climaticas, de seguridad o logisticas que limitan el movimiento.
- Cancelaciones de participantes o sesiones.

**Procedimiento:**
1. ETHNOS identifica las restricciones especificas y su impacto en el cronograma.
2. Genera escenarios alternativos (Escenario A: optimo; Escenario B: reducido; Escenario C: minimo viable).
3. Prioriza tecnicas segun su aporte a la densidad categorial.
4. Redistribuye recursos y reprograma sesiones.
5. Comunica al PI las implicaciones de cada escenario para la calidad del analisis.

**Ejemplo:** En el mismo proyecto anterior, dos participantes cancelan y el acceso a una localidad se retrasa 3 dias. ETHNOS propone: reasignar entrevistas a participantes alternos, condensar grupos focales en una sola jornada, y extender F3 para compensar con triangulacion documental.

### 4.3 Nivel 3: Accion Situada

**Definicion:** Resolucion pragmatica e inmediata en el terreno cuando la planificacion previa resulta insuficiente o inaplicable.

**Condiciones de activacion:**
- Situaciones imprevistas que rebasan los escenarios contingentes.
- Incidentes criticos (conflictos, emergencias, cambios subitos en el contexto).
- Oportunidades no previstas que enriquecerian el corpus (encuentros espontaneos, eventos comunitarios).

**Procedimiento:**
1. El equipo de campo registra la situacion en bitacora inmediata.
2. ETHNOS evalua si la accion situada afecta la integridad etica o metodologica del proyecto.
3. Si no hay riesgo etico: el equipo procede con criterio pragmatico y documenta la decision.
4. Si hay riesgo etico o de seguridad: suspension inmediata y consulta al PI y a Justitia (ODISEO).
5. Toda accion situada se registra como decision metacognitiva en la bitacora del proyecto.

**Ejemplo:** Durante una sesion de observacion, se produce una asamblea comunitaria no prevista que aborda directamente el tema de investigacion. El equipo decide registrarla como dato etnografico oportunista, documentando el contexto, los actores y la decision de incluirla en el corpus.

### 6.2 Riesgos Preclasificados por ETHNOS

Los siguientes riesgos deben evaluarse obligatoriamente en todo proyecto de campo:

**Categoria A: Logistica de Campo**

| Cod | Riesgo | Indicadores de Alerta Temprana |
|-----|--------|-------------------------------|
| A.01 | Dificultades de acceso a la comunidad o institucion | Demoras en respuestas de gatekeepers; permisos no gestionados a 5 dias del inicio |
| A.02 | Fallas en equipamiento tecnico (grabacion, fotografia) | Equipos sin prueba previa; baterias insuficientes; falta de memorias de respaldo |
| A.03 | Transcripciones inaudibles o incompletas | Ruido ambiental excesivo; sesiones sin control de calidad post-registro |
| A.04 | Incomprension de instrumentos por parte de participantes | Piloto no realizado; preguntas con lenguaje tecnico no adaptado |
| A.05 | Condiciones climaticas o de seguridad adversas | Alertas meteorologicas; reportes de conflicto en la zona |

**Categoria B: Densidad e Insuficiencia de Informacion**

| Cod | Riesgo | Indicadores de Alerta Temprana |
|-----|--------|-------------------------------|
| B.01 | Corpus insuficiente para alcanzar saturacion categorial | Menos de 3 fuentes diversas por eje tematico al llegar a F3 |
| B.02 | Sesgo en las fuentes (solo voces oficiales o solo una perspectiva) | Ausencia de diversidad en los perfiles de participantes |
| B.03 | Informacion recopilada no responde a la pregunta de investigacion | Primeras categorias emergentes no se alinean con los objetivos del proyecto |

**Categoria C: Temporalidad**

| Cod | Riesgo | Indicadores de Alerta Temprana |
|-----|--------|-------------------------------|
| C.01 | Cronograma insuficiente para el alcance propuesto | Mas del 30% de las sesiones reprogramadas en la primera semana |
| C.02 | Retrasos acumulados que comprometen la fase de analisis | F2 consume mas del 60% del tiempo total sin haber iniciado F3 |
| C.03 | Plazos de entrega incompatibles con la densidad requerida | PI solicita informe final antes de verificar saturacion |

**Categoria D: Etica y Seguridad**

| Cod | Riesgo | Indicadores de Alerta Temprana |
|-----|--------|-------------------------------|
| D.01 | Re-victimizacion de participantes en temas sensibles | Reacciones emocionales intensas durante sesiones; solicitudes de interrupcion |
| D.02 | Violacion de confidencialidad | Datos no cifrados en dispositivos moviles; transcripciones con nombres reales |
| D.03 | Conflicto con actores locales o gatekeepers | Resistencia explicita; solicitudes de censura o acceso a datos crudos |

## 7. Protocolo de Decision ante Incidentes

### 7.1 Incidentes Menores

**Ejemplos:** Cancelacion de una sesion, retraso de un participante, fallo tecnico puntual.

**Procedimiento:**
1. Reprogramar dentro del cronograma vigente.
2. Registrar en bitacora con codigo de incidente.
3. Verificar que el incidente no comprometa la densidad del corpus.
4. Continuar segun plan.

### 7.2 Incidentes Moderados

**Ejemplos:** Multiples cancelaciones, malestar en participantes, conflicto con gatekeeper, fallo tecnico que afecta varias sesiones.

**Procedimiento:**
1. Suspender temporalmente la actividad afectada.
2. Comunicar al PI de manera inmediata.
3. Activar plan contingente (Nivel 2).
4. Evaluar impacto en el cronograma y en la densidad categorial.
5. Documentar en bitacora con analisis de implicaciones.

### 7.3 Incidentes Criticos

**Ejemplos:** Amenazas de seguridad, violencia, emergencias de salud, riesgo etico grave, re-victimizacion detectada.

**Procedimiento:**
1. Suspension inmediata de toda actividad de campo.
2. Garantizar la seguridad fisica y emocional de participantes y equipo.
3. Notificar al PI y activar coordinacion con Justitia y Themis (ODISEO).
4. Evaluar si el proyecto puede continuar, requiere modificacion de alcance o debe cerrarse.
5. Registrar en bitacora con clasificacion de incidente critico y acciones tomadas.

## 8. Criterios de Alerta Automatica de ETHNOS

ETHNOS debe generar alertas proactivas al PI en los siguientes escenarios, sin esperar a que sean consultados:

1. **Alerta de insuficiencia temporal:** El cronograma propuesto es inferior al minimo requerido para las tecnicas y el alcance solicitados.
2. **Alerta de densidad:** El corpus recopilado hasta la fecha es insuficiente para responder las preguntas de investigacion con la profundidad categorial comprometida.
3. **Alerta de saturacion prematura:** Los datos comienzan a ser redundantes antes de cubrir todos los ejes tematicos previstos.
4. **Alerta de sesgo:** Las fuentes recopiladas carecen de diversidad suficiente (perspectivas, actores, tecnicas).
5. **Alerta etica:** Se detectan condiciones que podrian comprometer el anonimato, la confidencialidad o el bienestar de los participantes.
6. **Alerta de fragmentacion:** El volumen del corpus excede la capacidad de procesamiento en una sola tanda y se requiere estrategia de fragmentacion.
